# QA Checklist

Перед показом клиенту или публикацией в рабочий канал пройдите список.

## Деплой

- [ ] Railway service запущен без crash loop.
- [ ] PostgreSQL подключён.
- [ ] `DATABASE_URL` корректно задан.
- [ ] `ADMIN_IDS` задан.
- [ ] `ALLOWED_CHANNELS` содержит нужные каналы.
- [ ] `/doctor` не показывает критичных ошибок.

## Канал

- [ ] Бот добавлен администратором канала.
- [ ] У бота есть право публикации.
- [ ] Пользователь является администратором канала.
- [ ] `/check @client_news` проходит успешно.

## Источники

- [ ] Добавлен RSS-пакет или конкретные RSS.
- [ ] `/sourcecheck @client_news тема` показывает найденные материалы.
- [ ] CDN/image URL не используется как ссылка на статью.
- [ ] Левые картинки не прикрепляются.

## Контент

- [ ] `/news` создаёт одну новость.
- [ ] `/digest` создаёт подборку с блоками.
- [ ] `/day` формирует план контента.
- [ ] Markdown/HTML не ломает отправку.
- [ ] Внизу поста нет голых URL.
- [ ] CTA отображается как настроено.

## Безопасность

- [ ] Публикация требует подтверждения.
- [ ] Оператор не может менять критичные настройки.
- [ ] Viewer не может создавать и публиковать.
- [ ] `/audit` показывает действия.
- [ ] `/usage` и `/limits` работают.

## Продажа

- [ ] Есть демо-канал.
- [ ] Есть коммерческое описание.
- [ ] Есть цена для тестового этапа.
- [ ] Клиенту не передаются токены, `.env`, Railway-доступ и исходники без отдельной договорённости.


## Проверка релевантности темы

Если бот не создаёт новость или отклоняет материалы, используйте:

```text
/sourcecheck @client_news Telegram AI SMM
```

В диагностике смотрите строку `Причины отклонения`. Если много материалов отклонено как `не по теме запроса/канала`, уточните запрос или проверьте редакционный prompt канала.
